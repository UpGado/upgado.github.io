Last semester, while procrastianting on the night of a COMP160 exam, instead of studying, I decided to start a new fun project: I would try and develop a crack for some software! The idea is to alter the assembly code of a program in order to make it run without proper licensing. Assembly code is the code that is fed to the CPU that makes a program work. In other words, it is the most low-level form of code that a human can look at and understand. Nevertheless, I was familiar to Assembly thanks to COMP40, which is an awesome class at Tufts where students deal with a specific form of assembly code (AMD64) in an assignment called the Bomb. I just realized that what we do in that assignment is exactly what a person developing a crack would do: bypass and overcome checks instilled in a software in order to alter its behaviour. I was excited to start this projet mainly because I have no idea what I am doing, and I always looked at cracks as something magical that only geniuses can make. I wanted to give it a shot, so here we go!
